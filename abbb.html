2. System Architecture & Core Primitives

Singularity Flow enforces one non-negotiable architectural invariant: The Model-Independence Invariant. Probabilistic AI models (Copilot) are treated strictly as untrusted authoring participants. The lifecycle state machine, validation gates, verification receipts, and publication transactions are 100% deterministic and execute without an LLM.

The 4 Core Architectural Pillars

1. Git-as-a-Database

No PostgreSQL, Redis, or DynamoDB. Operational state lives in workflow.json on Story branches. Concurrency is arbitrated by native Git fast-forward push verification. History is tamper-evident and append-only.

2. Closed-Opcode Virtual Machine (GVM)

High-level Intent compiles into finite GVM Programs (KERNEL, AGENT, DEVICE, VERIFY, HUMAN_REQUEST). Refuses unbounded loops, graph cycles, and unrecovered side-effects at compile time.

3. Two-Plane Evidence Storage

Separates the Candidate Plane (content-addressed prospective code) from the Evidence Plane (append-only test receipts). Solves the circular reference flaw in traditional supply-chain tools.

4. Deterministic In-Memory Schema Migrations

Historical Git commits are never rewritten. Readers execute pure in-memory migrations that run twice and assert byte-identical hashes, guaranteeing forward compatibility across versions.

3. Security, Trust & Boundaries

Traditional AI tools fail enterprise security because they confuse AI agents with human users and allow agents to execute arbitrary shell scripts. Singularity Flow applies strict separation of authority and isolation membranes.

Core Security Principle: An AI Agent is software, not an approver. Approval authority requires an authenticated human identity matching an approved authority group. Self-approvals are flagged and audited.
Threat / Security Concern Enterprise Risk Singularity Flow Technical Control
Prompt Injection / Jailbreak Malicious prompt causes model to bypass security rules or delete code. Output Contracts: Kernel ignores prompt semantics. Only evaluates the emitted diff against strict filesystem write allowlists and protected paths.
Secret & Credential Exposure API tokens, Git credentials, or Jira keys leaked into committed files or prompts. Zero Secret Storage: Credentials stay in OS Keychain or VS Code SecretStorage. Ambient environment variables stripped; secrets actively redacted from logs.
Untrusted Workspace Mutation Model alters checked-out developer files or build configurations unexpectedly. Detached Worktrees: World-model analysis, candidate verification, and tool executions run in detached, isolated Git worktrees. Live developer workspace is untouched.
Supply Chain Tampering Upstream workflow rules or agent definitions silently modified mid-project. Content-Addressed Pinning: Stories pin an immutable snapshot of all rules and templates with per-file SHA-256 hashes (configuration-source.json). Changes require formal proposal PRs.
Consequential Tool Exploitation Autonomous agent runs destructive OS commands (e.g. rm -rf, arbitrary curl). Content-Addressed CAS Devices: SGOS sandbox devices execute with durable Tool Intent/Result receipts and confirmation-bound revocation.

4. Technology Stack & Runtime Topology

Singularity Flow is designed for extreme portability and zero infrastructure footprint. It requires no central daemon, no microservices, and no database servers.

Subsystem Technology Rationale & Architecture Boundary
Core Engine & CLI Node.js 20+ (Pure ESM .mjs) Standardized cross-platform runtime. Executes natively across macOS, Linux, and Windows without binary recompilation.
IDE Surface TypeScript 5.6+ / VS Code API Integrated into developer editor. Strictly decoupled: communicates exclusively via CLI subprocess calls and JSON snapshots.
State Persistence Git (v2.30+) Object Database Leverages content-addressed Git trees, refs, blobs, and commits. Replaces external databases with distributed, cryptographically auditable Git branches.
External Dependencies Ultra-Minimal: Only 4 runtime packages (yaml, tslib, @agentclientprotocol/sdk, @finos/calm-cli) Eliminates supply chain attack vectors. Zero bloated frameworks, zero ORMs, zero native C++ compilation bindings.
Process Supervisor Git Access Layer (GAL) Direct Git plumbing via git cat-file --batch-command. Replaces ad-hoc process spawning with reach-verified execution descriptors.

Self-Healing Diagnostics

The platform includes built-in operational healing commands:

  • sflow doctor: Inspects repository health, detects uncommitted journals, verifies remote reachability, and identifies stale subject locks.
  • sflow doctor --repair: Safely clears abandoned process locks and replays pending crash-recovery markers without data loss.
  • sflow audit --offline: Recomputes every cryptographic gate check from a bare clone with zero network connection.
  • sflow sync: Flushes pending local transactions to the remote Git server after connectivity interruptions.

7. Outage & Disaster Recovery Matrix (What Happens on Failures?)

Because Singularity Flow does not rely on a central server, its failure modes are localized, deterministic, and highly resilient. The matrix below outlines system behavior during infrastructure outages:

Infrastructure Outage System Behavior & Impact Recovery / Continuity Protocol
GitHub / Remote Git Server Outage Zero Data Loss
Developers continue working locally. Local git commits and stage transitions complete normally on the work branch. Push phase encounters network failure. 		Kernel writes a recovery marker under .git/singularity-flow/pending-publication/. When GitHub recovers, running sflow sync automatically performs the fast-forward push.
Artifactory / Package Registry Outage Zero Runtime Impact
Existing installed developers and CI runners are completely unaffected. Runtime makes zero calls to Artifactory. 		New developer onboardings are paused until Artifactory recovers, or developers can install via peer-to-peer signed tarballs.
GitHub Copilot / LLM Provider Outage Graceful Fallback
AI completions stop responding. However, the Singularity Flow kernel remains 100% operational. 		Developers switch to manual authorship mode (sflow --no-model). All specification checks, AST gates, test verifications, and approvals proceed manually without blocking.
Jira / Ticketing System Outage Decoupled Intake
Jira webhook syncs pause. 		Stories start using natural-language sentence intake (e.g. sflow start "Implement OAuth" --work-id ENG-101). Intent is pinned locally in source.json. Re-syncs to Jira when online.
Workstation Crash / Sudden Power Loss ACID Integrity
Crash occurs mid-command during file writing or index computation. 		All disk writes use atomic swap (writeAtomic: write to temp file then rename). Incomplete writes are discarded. Running sflow doctor automatically resolves the transaction journal.
